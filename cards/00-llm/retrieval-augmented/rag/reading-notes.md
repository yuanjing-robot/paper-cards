# 精读笔记：RAG

> 📄 对应论文：[Retrieval-Augmented Generation for Knowledge-Intensive NLP Tasks](https://arxiv.org/abs/2005.11401)
> 整理者：@zeng417
> 最后更新：2026-10-05

---

## 1. 问题与动机

- 序列到序列模型把知识全存在权重里（参数化记忆），有三个结构性问题：**知识难更新**（要重训）、**容易编造**（幻觉无据可查）、**不可溯源**（说不出出处）。
- 开放域 QA 这类「知识密集型任务」恰好吃这三点：答案就是一条事实，错了就是错了。
- 已有两条路：纯生成（T5/BART）与「检索 + 阅读理解」（DPR + 抽取式 reader）。这篇论文想兼得两者：**让生成模型带一个可检索的外部记忆**，且端到端联合训练。

## 2. 核心方法

- **两套记忆**：
  - 参数化记忆：BART-large 生成器（约 400M 参数）；
  - 非参数化记忆：Wikipedia 2020 约两千一百万篇文档，用 DPR 的稠密检索（query/doc 双编码器 + FAISS 索引）取 top-k。
- **融合方式**：把问题与检索到的 k 篇文档分别拼接送入生成器，对 k 个输出做**边缘化**（概率层面融合）——RAG-Sequence 对整句归一化，RAG-Token 逐 token 归一化（后者可让不同 token 依赖不同文档）。
- **端到端训练**：query 编码器与生成器一起，以 margin likelihood 目标联合优化——检索器不是冻结的，会学会"为生成而检索"。

## 3. 关键结果

- 开放域 QA：NQ EM 44.5，超过 DPR（41.5）、T5-11B+SSM（36.6）等一众更大或专精的基线（论文报告）；TriviaQA 上与最强抽取式方法相当。
- 生成任务（Jeopardy 问题生成）：BLEU 与事实性均优于纯 BART；**人工评估中 RAG 生成的具体事实错误显著更少**。
- 与纯参数化方法对比：模型只有 3B 以下规模却在开放域 QA 上打败 11B 的 T5+SSM——外部记忆的性价比。
- 附带的可爱发现：RAG 能生成比 DPR 或纯 BART 都更"多样且具体"的答案。

## 4. 批判性思考

- **检索质量是天花板**：召回不到正确文档，生成再强也没用；论文用的 DPR 嵌入较老，这是"冻结检索器 + 老索引"路线的共同软肋。
- **端到端训练检索器不现实**：在数千万文档上反向传播 query 编码器代价极高，实际很多复现直接用冻结检索器。
- **知识源单一**：只挂 Wikipedia，时效性、私域知识、多跳推理都不覆盖。
- **延迟翻倍**：每次生成都要过一遍检索 + k 次拼接前向，在线服务成本明显增加。
- 与后来的 REALM 相比，无法更新索引内的知识（REALM 支持（半）实时更新索引）。

## 5. 个人收获

- 全文最有价值的不是模型，而是一个**框架级判断**：知识放参数里（贵、稳、不可控）还是放外部库里（便宜、可更新、可溯源）是根本性 trade-off。今天企业里"要不要微调还是上 RAG"的争论，2020 年这篇论文已经把框架画好了。
- 「对多个候选做概率边缘化」是个很优雅的融合姿势：不武断选一篇文档，而是让证据在概率层面自然加权——这种"软选择"思路在很多场景（多专家路由、多模型集成）都适用。
- 从产业视角看，这篇论文是整个 **向量数据库 + LLM 应用** 生态的起点文献；读它最好带着现在的工程问题（chunk 怎么切、重排怎么做）回头对照，会发现原始论文其实相当克制。

## 6. 延伸阅读

- DPR（Karpukhin et al., 2020）：本文检索器的出处
- REALM（Guu et al., 2020）：同期工作，端到端更新语言模型的知识索引
- Atlas / RETRO：检索增强的规模化后续
- FiD（Fusion-in-Decoder）：更实用的"拼接式"融合替代边缘化
- InstructGPT 本卡片库笔记：[InstructGPT](../../alignment/instructgpt/)（参数化路线的对齐改进，可与 RAG 互补）
