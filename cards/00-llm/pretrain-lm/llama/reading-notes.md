# 精读笔记：LLaMA

> 📄 对应论文：[LLaMA: Open and Efficient Foundation Language Models](https://arxiv.org/abs/2302.13971)
> 整理者：@zeng417
> 最后更新：2026-10-05

---

## 1. 问题与动机

- GPT-3 之后，最强模型全部闭源，学术界做不了深入研究，工程界也难以私有部署。
- 这篇论文回答两个问题：① **推理成本**方面——给定目标质量，能否用更小的模型 + 更长的训练换来一个更便宜的模型？② **开放性**方面——完全用公开数据，能不能把性能做到当时一线水平？
- 出发点是 Chinchilla（2022）的结论：很多大模型其实"参数喂多了、数据喂少了"，最优配方是参数和数据大致同步放大。

## 2. 核心方法

- **规模哲学**：与其训一个巨模型然后少训，不如训一个中小模型但喂 1.4T tokens（GPT-3 的近 5 倍）——推理便宜，虽然训练贵一点。
- **四个尺寸**：7B / 13B / 33B / 65B，都是标准 Transformer decoder，叠加几个成熟的工程优化：
  - **RMSNorm**（Pre-Norm 位置）替代 LayerNorm；
  - **SwiGLU** 激活函数（FFN 维度调整为 2/3 保持参数量对齐）；
  - **RoPE 旋转位置编码**替代绝对位置编码；
  - AdamW + cosine 学习率 + 较大 batch。
- **数据**：只用公开数据（C4、GitHub、维基百科、书籍、ArXiv、StackExchange），按领域采样配比，强调数据质量与多样性，20% 语料不含中文（多语言能力有限是已知取舍）。

## 3. 关键结果

- 论文报告：13B 在多数公开基准上超过 GPT-3 175B；65B 与 Chinchilla-70B、PaLM-540B 相当；65B MMLU 63.4（few-shot）。
- 代码能力（HumanEval）、多语言能力优于同尺寸开源模型；数学推理仍弱（后续版本改进）。
- 推理成本角度：13B 单卡可跑，65B 训练约 2048 块 A100 × 21 天，性价比显著优于同性能闭源模型。

## 4. 批判性思考

- **只是 base model**：没有 RLHF / 对齐，直接对话会产生有害内容，需要自己接对齐流程（后来的 LLaMA 2-Chat 才补上）。
- **许可非商用**：研究可用但商用受限，权重一度只能申请获取（泄露版反而推动了生态，这是个讽刺的细节）。
- **数据截止旧、中文弱**：知识新鲜度和中文任务表现都不理想。
- **训练贵推理省的 trade-off**：对算力紧张的团队，「1.4T tokens」的长训成本同样遥不可及，省钱只在推理端成立。

## 5. 个人收获

- 「模型尺寸不是性能的唯一变量，**数据配比与质量**才是可以持续优化的杠杆」——LLaMA 把 Chinchilla 的理论配方第一次完整落到了开源上。
- 那几个工程优化（RMSNorm / SwiGLU / RoPE）说明：到 2023 年，架构层面的"创新"基本收敛，剩下的竞争在**数据、训练稳定性与工程细节**。这对判断论文含金量很有用：只改架构没动数据的工作，增益通常有限。
- 生态视角：开源权重 → 微调脚本（Alpaca 用 5 万条指令数据）→ 垂直应用爆发。**开放本身会成为技术进步的加速器**，而不只是道德姿态。
