# 精读笔记：GPT-3

> 📄 对应论文：[Language Models are Few-Shot Learners](https://arxiv.org/abs/2005.14165)
> 整理者：@zeng417
> 最后更新：2026-10-05

---

## 1. 问题与动机

- BERT 路线的「预训练 + 微调」有个根本痛点：**每个任务都要标注数据、单独微调、单独部署**，模型是"通用"的，流程却不通用。
- 这篇论文想验证一个激进假设：语言模型本身放大到足够大，能否**不微调**、只靠自然语言指令和几个示例就完成任务？
- 与 GPT-2 的区别不只是参数变大，更是目标变了：从「预训练 + 任务微调」变成「一个模型 + 一个 prompt 接口解决所有任务」。

## 2. 核心方法

- **架构**：沿用 GPT-2 的 decoder-only Transformer（部分层用交替的稠密/局部带状稀疏注意力），但放大到 175B：96 层、隐藏 12288、96 头、上下文 2048。
- **In-context learning（上下文学习）**：不更新任何权重，把任务说明 + 少量输入输出示例拼进 prompt：
  - zero-shot：只有任务描述；
  - one-shot：1 个示例；
  - few-shot：10~100 个示例（受 2048 上下文限制）。
- **数据**：以过滤后的 Common Crawl 为主（约 570GB），混合 WebText2、Books1/2、Wikipedia，共约 300B tokens；论文特别强调做了文档级去重和模糊去重防止测试集泄漏。
- **训练**：约 3.14×10^23 FLOPs，作者在正文报告按当时云价格估算数百万美元量级。

## 3. 关键结果

- 论文报告：few-shot 设置下 TriviaQA 71.2、LAMBADA 86.4，大量任务追平或超过微调基线；少数任务（如 GSM8K 数学题，few-shot 仅约 17%）明显不行——这为后来的思维链（CoT）埋下伏笔。
- **规模曲线**：几乎所有任务上 zero/one/few-shot 性能随参数量持续上升，且 few-shot 相对 zero-shot 的增益也在变大——"模型越大，越会利用上下文里的示例"。
- 宣示性结论：预训练语言模型本身就是一个「元学习器」，prompt 是它的任务接口。

## 4. 批判性思考

- **评估靠人工写 prompt**：同一任务不同 prompt 表现差异巨大，结果对措辞敏感，可复现性一般。
- **数据问题**：Common Crawl 的偏见、有毒内容被原样学进去；训练数据与测试集的泄漏只能"尽量"排除。
- **不可复现**：训练成本决定了只有极少数机构能验证，开源社区当时无能为力（这也是 LLaMA 出现的动机）。
- **in-context 机制是黑箱**：它到底是"学习"还是"模式匹配激活"，论文没有回答。
- **上下文 2048 太短**：few-shot 示例数量、长文档都受硬性限制。

## 5. 个人收获

- 「few-shot」这个词有点误导：模型并没有"学"新知识，更像是**预训练时见过的模式被示例定位并激活**。这个视角让我理解了为什么 prompt 里示例的格式、顺序影响那么大。
- 规模本身会带来质变（后来的「涌现能力」论文专门论证）：判断一个能力要不要做，先看它随规模的曲线形状，而不是只看当前小模型上跑不跑得通。
- 工程启示：**统一接口（prompt）比统一权重更重要**。GPT-3 之前大家共享预训练权重，GPT-3 之后大家共享同一个"任务 API"，这是产品形态和科研范式的双重转折点。
