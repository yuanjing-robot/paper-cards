# 精读笔记：Chain-of-Thought

> 📄 对应论文：[Chain-of-Thought Prompting Elicits Reasoning in Large Language Models](https://arxiv.org/abs/2201.11903)
> 整理者：@zeng417
> 最后更新：2026-10-05

---

## 1. 问题与动机

- 大模型在数学应用题、逻辑推理这类**多步任务**上表现与参数量不匹配：题目并不难，但「一步出答案」的输出方式强迫模型把多步计算压进一个隐层前向传播里。
- GPT-3 论文已经暴露：175B few-shot 在 GSM8K 上只有约 17%，是明显短板。
- 一个朴素的观察：人解题会打草稿。能否把「草稿」显式地放进 prompt 里，让模型模仿？

## 2. 核心方法

- **方法简单到只有一句话**：在 few-shot 示例中，把每个问题的**中间推理步骤**（"先算单价，再乘数量……"）连同最终答案一起写出来；测试时模型自然先输出推理链，再给答案。
- 不微调、不引入新参数、不依赖外部工具——纯 prompt 层面的改动，8 个示例即可。
- 实验覆盖 3 个模型族（GPT-3、LaMDA、PaLM）× 4 类算术/常识/符号推理任务，控制了示例顺序、prompt 措辞等变量。
- 关键实验设计：同一批任务对比「标准 prompting（只给问答对）」vs「CoT prompting（问答 + 推理链）」，并扫描模型规模。

## 3. 关键结果

- 论文报告：GSM8K 上 PaLM 540B 从标准 prompting 的 17.9% 提升到 CoT 的 56.9%，**超过当时在 GSM8K 上微调 + 输出验证器的 SOTA（约 55%）**——prompting 打赢了微调。
- **规模阈值现象**：CoT 只在约 100B+ 参数的模型上带来大幅增益；10B 以下不升反降（模型根本模仿不出有效推理链）。
- 增益随任务"多步程度"增加而放大，单步任务收益很小——符合"草稿分解计算"的解释。

## 4. 批判性思考

- **是激发不是新增**：CoT 只是让模型说出本来就在隐层里"做过"的计算；对小模型无效说明它不是通用解，依赖强 base model。
- **推理链 ≠ 真实计算过程**：链对答案错、答案对链错的情况都常见，推理链的可解释性是"看起来可解释"，不能当证据用。
- **分布外脆弱**：题型变化大、数字更极端时成绩明显下滑；"多步推理能力"在泛化上远不如人。
- **成本**：推理链多出几十至几百个输出 token，延迟与费用按比例上涨。

## 5. 个人收获

- 方法论上最大的启发是：**有时候不需要新模型，只需要把监督信号换个形式放进上下文**。标注一份数据、训练一个模型的成本，可能等价于"写清楚 8 个示例"。
- 规模阈值（100B+ 才生效）提醒我：评估一个 prompting 技巧时要**画规模曲线**，在小模型上验证出来的结论未必能外推。
- 这篇论文是后来整个"慢思考"谱系（Self-Consistency、Tree-of-Thought、o1/R1 的长推理）的源头：**把"更多计算"从隐层搬到显式 token 序列**，用推理时间的自回归开销换准确率——这个 trade-off 至今仍是推理模型的基本盘。

## 6. 延伸阅读

- ReAct（Yao et al., 2022）：推理链 + 工具行动，CoT 走向 Agent
- Tree-of-Thoughts（Yao et al., 2023）：把链升级为可搜索的树
