# 深度阅读：OpenVLA

> 📄 对应论文：[OpenVLA](https://arxiv.org/abs/2406.09246)
> 整理者：@kingdream-cn
> 最后更新：2026-10-30

---

## 1. 问题与动机

- 具身智能最烦人的就是泛化：稍微换个背景、或者来个没见过的杯子，机器人往往就傻了。
- 之前卡在哪：谷歌的 RT-2 泛化确实好，但它闭源。别人既没法复现它的读数，也别想拿它在自己的机器人上微调。想比一下 RT-2-X 怎么办？OpenVLA 自己在致谢里写了答案——得找 DeepMind 要一个 RT-2-X API 的 alpha 权限（p11）。
- OpenVLA 就是冲着这个壁垒来的：直接放出一个 7B 的开源底座，代码、权重、数据配比全开（§4），顺手把消费级显卡上的落地方案也跑通了。

## 2. 核心方法

- 底座选的是 Prismatic-7B：600M 参数视觉编码器 + 2 层 MLP projector + Llama 2 7B（§3.1）。
- 取巧的第一处是视觉塔。光用 SigLIP 认得出语义、但空间对不准，于是再挂一个 DINOv2 提低层空间特征，两路各编码一遍、特征按通道拼起来（§3.1；「DINOv2 出低层空间信息、SigLIP 出高层语义」是论文 §2 自己的说法）。要说清楚：**这个融合方案不是 OpenVLA 设计的，它只是挑了自带融合的 Prismatic 当底座。**
- 输出动作那步更偏工程：连续动作的每个维度**各自**离散，区间取训练数据该维的 1st–99th 分位、在里面等宽切 256 档（§3.2；用分位而不是 RT-1 的 min-max，是为了不让几个离群动作把区间撑烂、把粒度吃掉）。接着拿这 256 个动作 token 去覆盖 Llama 词表里使用率最低的那 256 个——因为 Llama tokenizer 只预留了 100 个 special token，塞不下。等于把机器人控制变成了文本补全，损失只在动作 token 上算（§3.2）。
- 数据是从 Open X-Embodiment 里挑出来的 970k 条机器人演示，最终混合取 27 个数据集（§3.3、表 3）。

## 3. 关键结果

- 主读数：7B 在 WidowX 和 Google 机器人的 29 个任务上，比闭源的 RT-2-X（55B）高 16.5 个绝对百分点（摘要 p1、§1 p2）。分项看是 BridgeData V2 上 70.6% 对 RT-2-X 的 50.6%（表 4），Google robot 上 85.0% 对 78.3%（表 6）。
- **别读成全面反超**：语义泛化那一类还是 RT-2-X 更高，图 3 的图注自己写了「除语义泛化外」。
- 最吸引人的其实是微调成本：rank=32 的 LoRA 只更新 1.4% 参数就追平全量微调，单张 A100 跑 10–15 小时，算力省 8 倍（§5.3、表 1）。
- 推理侧上 4-bit 量化，显存压到 7.0 GB，成功率 71.9% 对 bfloat16 的 71.3% 基本不掉（表 2，逐任务明细在表 5）；反倒是 int8 会掉到 58.1%，这点不太符合直觉。图 6 画的是各张卡的吞吐，不是成功率。

## 4. 批判性思考

- 输入只吃单张 RGB，既没有历史帧也没有本体感知（关节角之类）——§6 第一条局限自己点名了，复杂场景抓取容易翻车。
- 推理太慢。4090 上约 6 Hz，而且论文明说这个数字不含编译、投机解码之类的加速（§3.5）；§6 第二条承认 ALOHA 那种 50 Hz 的高频控制现在跑不了。放到室外高动态任务上，这个速度直接瘫痪。
- 单一指令的高精度微操，轨迹平滑度还是打不过 Diffusion Policy。这点论文在 §5.2 结尾自己认了，并把 action chunking 和时序平滑列成未来工作——也就是说它没做。
- 还有个容易踩的口径坑：表 1、表 2 用的不是主模型，而是「数据混合更小 + 视觉塔只留 SigLIP」的那个版本（p10 脚注 4）。往外引数的时候特别容易被当成 7B 融合版的读数。
- 另外整篇的成功率上限也就 <90%（§6 第三条自己承认），离产线可用还差一段。

## 5. 个人收获

- 有两个点可以直接借鉴到以后的开发里。一是 DINOv2+SigLIP 的双视觉路线，纯语义大模型做底盘或机械臂导航确实容易有动作漂移，加空间特征融合是刚需。二是它复用 LLM 废弃 Token 做动作离散化，这思路绝了，特别适合算力有限要在普通 GPU 上做开发的场景。这套逻辑以后完全可以套进我们自己的 ROS 2 开发节点里，用 Trae 写个定制的智能体助手跑跑看。
