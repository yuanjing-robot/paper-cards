## 🧠 Knowledge · 通用知识点

### 知识点 1：自注意力机制 (Self-Attention)
- **内容**：通过 Query、Key、Value 的矩阵运算，计算序列中每个位置和所有位置的关联程度，从而动态聚合信息。
- **来源**：论文第 3.1 节，整本书的核心
- **可迁移到**：
  - NLP：所有 Transformer 类模型
  - CV：ViT、DETR 等视觉 Transformer
  - 语音：Conformer、Whisper
  - 图神经网络：Graph Transformer
  - 推荐系统：用注意力建模用户行为序列
- **我的理解**：
  - 注意力的本质是"加权求和"，权重由元素间的相似度动态计算
  - 传统 CNN/RNN 的权重是固定的（卷积核 / 门控参数），注意力的权重是输入相关的
  - 这就是注意力更灵活、表达能力更强的原因

### 知识点 2：并行计算的巨大价值
- **内容**：在深度学习中，可并行的架构往往最终会胜出，因为并行意味着：训练更快 → 可以做更多实验 → 可以用更大的数据和模型 → 效果上限更高。
- **来源**：论文第 5 节的训练效率对比
- **可迁移到**：
  - 架构设计：优先选择可并行的方案
  - 工程优化：GPU 就是为并行设计的，越并行越能发挥硬件能力
  - 研究方法：速度快的方法迭代效率高，更容易做出成果
- **我的理解**：
  - 很多时候，"更快"本身就是最大的优势
  - RNN 不是效果不行，而是训练太慢，限制了它的规模
  - Transformer 的胜利，某种意义上是"并行计算"对"串行计算"的胜利

### 知识点 3：归纳偏置与数据效率的权衡
- **内容**：强归纳偏置（如 RNN 的序列顺序假设、CNN 的局部性假设）在数据少时能帮忙，但数据多时会限制模型的上限。弱归纳偏置（如 Transformer 的注意力）数据效率低，但上限更高。
- **来源**：对比 RNN/CNN 和 Transformer 的特点
- **可迁移到**：
  - 模型选择：数据多不多？不多就选归纳偏置强的
  - 方法设计：归纳偏置加多少合适？
  - 预训练的意义：预训练 = 用大数据弥补弱归纳偏置
- **我的理解**：
  - 归纳偏置是"先验知识"，对的时候能省很多事，错的时候就是天花板
  - 大数据时代，"让数据说话"往往比"人为假设"效果更好
  - 这也是为什么 Transformer 能横扫各个领域 — 它的归纳偏置最弱，最灵活

## 📜 Law · 实验验证的领域规律

### 规律 1：自注意力可以有效建模序列依赖关系
- **规律描述**：在序列建模任务中，自注意力机制可以替代 RNN/CNN，捕捉长距离依赖，且效果更好。
- **本文证据**：在 WMT 翻译任务上，纯注意力架构超过了 RNN 和 CNN 的 SOTA。
- **其他论文的佐证**：
  - BERT 证明了 Transformer 在理解类任务上也极强
  - GPT 证明了生成类任务同样好用
  - ViT 证明了在 CV 领域也能用
  - 几乎所有后续 SOTA 都是 Transformer 架构
- **反例 / 例外**：
  - 非常小的数据集上，RNN 可能更好（归纳偏置的优势）
  - 某些特定结构任务（如严格的层次结构），专门的归纳偏置可能更有效

### 规律 2：Scaling Law — 模型越大、数据越多，效果越好
- **规律描述**：Transformer 架构的性能随模型大小、数据量、计算量的增加而可预测地提升，且似乎没有明显的饱和点。
- **本文证据**：base 模型到 big 模型，效果有显著提升（论文表 3）。
- **其他论文的佐证**：
  - GPT-3 系统验证了 scaling law
  - Chinchilla 进一步优化了数据和计算的比例
  - 无数工作证明了 Transformer 的可扩展性
- **反例 / 例外**：
  - 小到一定程度后，可能不成立
  - 任务本身有上限（比如某个数据集的人类水平）

### 规律 3：多头注意力比单头好
- **规律描述**：把注意力分成多个头，各自学习不同的注意力模式，再拼接起来，效果比单头注意力好。
- **本文证据**：论文表 5（M0 是单头，多头效果更好）。
- **其他论文的佐证**：几乎所有 Transformer 变体都在用多头注意力，成为标准配置。
- **反例 / 例外**：
  - 头太多也不行，每个头的维度太小
  - 某些任务可能只需要少数几个头

## 🛠️ Experience · 工程 / 算法经验总结

### 训练技巧
1. **学习率 warmup 很重要**：
   - 训练初期学习率从小线性增加到峰值，再衰减
   - 对 Transformer 的稳定训练很关键
   - 公式：`lr = d_model^(-0.5) * min(step^(-0.5), step * warmup_steps^(-1.5))`

2. **残差连接 + LayerNorm 是深度网络的标配**：
   - 每个子层都用 Pre-LN 或 Post-LN
   - 没有残差连接，深的 Transformer 根本训不起来

3. **Dropout 加在注意力之后**：
   - attention 权重 dropout
   - 子层输出 dropout
   - 防止过拟合

### 调参经验
1. **学习率和模型维度相关**：
   - 模型越大，学习率应该越小
   - 论文用的是 `lr = 1/sqrt(d_model)` 缩放

2. **头数和维度要匹配**：
   - `d_model` 必须能被 `h`（头数）整除
   - 每个头的维度 `d_k = d_model / h`
   - 一般 d_k = 64 效果比较好

3. **位置编码的选择**：
   - 正弦编码和可学习的效果差不多
   - 正弦编码可以外推到更长的序列（理论上）
   - 实际中很多人用可学习的，因为更简单

### 架构设计经验
1. **编码器-解码器结构适合 seq2seq 任务**：
   - 编码器处理输入，解码器生成输出
   - 编码器-解码器注意力桥接两者
   - 这是翻译、摘要等任务的标准结构

2. **掩码注意力是自回归生成的关键**：
   - 解码器的自注意力要加掩码，防止看到未来的词
   - 这保证了训练和推理的一致性

## ⚠️ Lesson · 踩坑教训与避坑指南

### 坑 1：学习率太大导致训练不稳定
- **现象**：loss 一开始就爆炸，或者训着训着突然变成 NaN
- **原因**：Transformer 对学习率比较敏感，太大了容易不稳定
- **怎么避**：
  - 一定要用 warmup
  - 学习率按 `1/sqrt(d_model)` 缩放
  - 刚开始训练时监控 loss，不对劲就降学习率

### 坑 2：位置编码加错地方 / 加的方式不对
- **现象**：模型效果很差，或者对位置不敏感
- **原因**：位置编码没加对，或者和 embedding 的融合方式不对
- **怎么避**：
  - 位置编码要加到输入 embedding 上，而不是替换
  - 确保位置编码的维度和 embedding 维度一致
  - 可以先试试可学习的位置编码，比较稳妥

### 坑 3：注意力 mask 写错导致信息泄露
- **现象**：训练时效果很好，推理时效果差很多
- **原因**：解码器的掩码注意力写错了，训练时让模型看到了未来的词
- **怎么避**：
  - 仔细检查 causal mask 的实现
  - 用一个小例子手动验证：给前缀输入，看模型能不能预测出和训练一致的结果

### 坑 4：batch size 太小导致 LayerNorm 不稳定
- **现象**：小 batch 训练时效果波动大
- **原因**：LayerNorm 在 batch 太小的时候统计量不准
- **怎么避**：
  - 尽量用大一点的 batch size
  - 或者用 RMSNorm 等更稳定的归一化方式

## 🎯 可复用的方法论 / 框架

### 分析框架："归纳偏置 vs 数据效率"分析框架
- **是什么**：分析一个模型/方法时，可以从"归纳偏置有多强"和"数据效率"的角度看
- **怎么用**：
  - 强归纳偏置 → 小数据好，大数据有天花板
  - 弱归纳偏置 → 小数据差，大数据上限高
  - 根据你的数据量和任务，选合适的
- **能用到什么地方**：模型选型、方法设计、分析论文

### 实验方法论：消融实验的标准做法
- **方法**：
  1. 先有一个完整模型（所有模块都有）
  2. 每次去掉/替换一个模块，看效果降多少
  3. 从而知道每个模块的贡献
- **适用场景**：几乎所有论文都需要做消融来证明各模块的作用
- **本文的消融**：表 5，依次去掉多头、改位置编码、改 dropout 等
