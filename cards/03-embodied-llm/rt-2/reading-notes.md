# 深度阅读：RT-2

> 📄 对应论文：[RT-2](https://arxiv.org/abs/2307.15818)
> 整理者：@kingdream-cn
> 最后更新：2026-10-28

---

## 1. 问题与动机

- 这篇论文想干的事，是把 VLM 在互联网上学到的那一大堆常识，直接接到机器人的底层动作上。
- 以前卡在哪：做实体机器人的都有个老毛病，上层和下层是两拨东西。论文 §1（p2）讲得挺直白——这类方案里大模型只干「更高层」的活，本质上是当了个状态机，把人话拆成 pick、place 这种原子技能，再丢给另一套低层控制器去执行。而那套真正管动作的控制器，训练时压根没沾过互联网模型的语义知识。
- 为什么不能靠多采数据解决：真机数据太贵了。论文 §1 给的对比是，最强的 VLM/LLM 吃的是数十亿级图文，机器人这边短期内根本攒不出同量级的交互数据。所以「多采点机器人数据，让底层自己悟出理解能力」这条路走不通。
- 于是问题变成一句话：能不能让预训练 VLM 直接下场做低层控制，把泛化和语义推理能力从网络预训练里带进来？

## 2. 核心方法

Google 这套办法说白了就一句：把机器人动作当成一门外语，塞进 VLM 的词表里，让它照旧一个 token 一个 token 往外吐。论文给这类模型起了个名字，VLA（vision-language-action）。

拆成五步：

1. **动作先切成整数。** 一个动作 = 末端执行器的 6-DoF 位移和旋转 + 夹爪伸出量 + 一个终止命令，一共 8 个整数。前 7 个是连续量，均匀切成 256 档；终止命令本来就是离散的，不分档。（§3.2。别漏第 8 个，不然「8 个整数」数不出来。）
2. **整数怎么变 token，两个底座做法不一样。**（§3.2，这步最容易写错）
   - PaLI-X：它的 tokenizer 里 1000 以内的整数各自都有唯一 token，那就直接用数字本身的 token，最省事；
   - PaLM-E：没这个便利，于是把词表里 256 个最少使用的 token 抢过来充当动作词表。论文说这属于 symbol tuning 的一种（Wei et al., 2023）。

   所以「映射到不常用的 token」只是 PaLM-E 那条路，不是所有 RT-2 都这样。
3. **拼成一条样本。** 动作按 `terminate Δpos_x Δpos_y Δpos_z Δrot_x Δrot_y Δrot_z gripper_extension` 的顺序用空格连成一串；输入那边套标准 VQA 模板「Q: what action should the robot take to [任务指令]? A:」。这步是整个办法能跑通的前提——机器人轨迹被伪装成一道视觉问答题，才谈得上跟网络数据进同一个 batch。
4. **混合微调（co-fine-tuning）。** 最精髓的一点。不是拿机器人数据朴素地 finetune 就完事，而是把机器人轨迹和原来那批互联网 VQA 数据掺在一起继续训，靠调高机器人数据的采样权重来配比（附录 B：PaLI-X 约 50%，PaLM-E 约 66%）。这样模型学会吐动作的同时，不会把原来认图识物的脑子洗掉。
5. **输出要约束住。**（§3.2 Output Constraint，容易被忽略）真机不接受乱码，所以只要当前 prompt 是机器人任务，解码时就只从合法的动作 token 里采样；跑普通视觉问答时，整个自然语言词表照常放开。

## 3. 关键结果

- **已见任务上其实没赢。** 训练过的任务，RT-2 成功率 91–93%，RT-1 是 92%（附录 H 表 4）。动作精度基本没涨，这篇论文的价值不在这里。
- **泛化才是重点。** 没见过的物体、背景、环境，RT-2-PaLI-X-55B 平均 62%，RT-1 32%，差了一倍（同样在表 4）。这些结论背后是大约 6,000 次真机试验（摘要、§4）。
- **涌现能力，像开盲盒。** 机器人数据里从没出现过的指令，它能执行。论文 §4.4 把这类能力分成三种：符号理解、推理、人识别。举几个原文里的例子：
  - 「把草莓放进正确的碗」——它得知道草莓要跟同类水果放一块；
  - 「把可乐罐移给戴眼镜的人」——这是人识别那类，靠的是网上预训练攒下的常识；
  - 量化结果在表 5：RT-2 平均 60%，RT-1 只有 17%。
- **会自己盘逻辑。** 把指令改成先规划再动作（思维链），它能做多步推理。图 7 那段真实 rollout：问它「我要砸钉子，场景里哪个东西能用」，它先吐一个 `Rocks.`，后面紧跟一串动作 token 去抓石头。§1 还举过一个「谁累了该喝什么 → 能量饮料」。
- **最能说明问题的是消融实验。** 模型越大泛化越好；而且 co-fine-tuning 明显强于只用机器人数据朴素微调（附录 H 表 6）。网络知识确实迁移进来了，不是玄学。

## 4. 批判性思考

- **物理技能变不出来。** RT-2 更像个「排列组合大师」，用高维语义去重新调用已有的基础动作；训练集里没有的动作，它照样不会。这不是我替它总结，论文 §5 第一条局限自己写了：加了网络预训练，机器人并没有因此获得任何新的运动能力，技能还是被机器人数据的分布框住，变的只是使用方式。附录 G 还老实列了不会的清单——抓指定部位（比如把手）、用毛巾擦拭、工具使用、折毛巾，以及要绕几道弯的长程推理。图 9 是在没见过的物体动力学上翻车的实录。
- **延迟和算力这道坎。** 55B 的模型太吃算力，扔在云端 multi-TPU 上跑，控制频率只有 1–3 Hz（§3.3）。放到需要实时避障、高动态的场景，比如移动底盘上，这个延迟是要出事故的，端侧本地部署目前别想。论文 §5 第二条认了这个瓶颈，说以后靠量化和蒸馏解决。
- **底座被人卡着脖子。**（这条最容易被漏，是论文 §5 自己列的第三条局限）能拿来改造成 RT-2 的通用 VLM 数量极少，而且基本闭源。作者直接喊话：希望多出一些开源模型（点了 llava-vl），也呼吁闭源模型开放微调 API，说只要有这些就够造 VLA 了。后来 OpenVLA 那批开源复现，就是冲这个缺口来的。
- **倍数口径对不上，引用要小心。** §4.4 正文说涌现技能比 RT-1 好「3 倍以上」，附录 H.2 正文写「2x 到 3x」，而表 5 的原始均值是 60% 对 17%，算下来约 3.5 倍。三处不一致，本卡片一律以表格数值为准。
- **论文没给的东西。** 机器人演示到底多少条、训练烧了多少 TPU 时和多少钱，全文都没写（附录 B 只给了数据构成和混合比例）。想看绝对成本，这篇给不了。

## 5. 个人收获

最大的启发是不要总是死磕复杂的底层网络结构设计。只要把高维语义决策和低维控制通过简单的 Tokenization 对齐，就能直接借力 NLP 和 CV 领域成熟的大模型能力。这对我之前在本地把小语言模型（SLM）和各种视觉方案组合去跑真机控制，提供了一个非常清晰的多模态的融合思路。

## 6. 延伸阅读（可选）

- 动作空间到底怎么定义的，去看前作 RT-1（Brohan et al., 2022，arXiv:2212.06817），本文的离散化方案直接沿用它的。
- 两个 VLM 底座之一 PaLM-E（Driess et al., 2023，arXiv:2303.03378），「用自然语言去规划行动」这条线的上游。
- 项目主页 [robotics-transformer2.github.io](https://robotics-transformer2.github.io) 值得多刷几遍，真机演示实况比文字直观得多。注意主页上那些是作者自己的 demo 录像，算实验证据，不算第三方解读。
- 想自己动手跑 VLA，就接 OpenVLA（arXiv:2406.09246）——它正是冲着上面第三条局限（底座少又闭源）做的开源复现，代码和权重都放出来了。
